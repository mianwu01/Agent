# Pivot-and-Probe v6: exploration started 2026-10-04

This run follows `p4_handoff_v6_2026-10-03.zip`. Earlier A/B/C screening,
certificate, human-adjudication and G1-closeout rules are historical experiments;
they do not gate this v6 pilot. Thresholds guide exploration and are not used
as stopping requirements. Existing outputs remain available.

## First batch

Reuse the 912 saved default-mode Luna trajectories. Uniformly sample 12
partner-turn starts from mobile-data/MMS trajectories, without judge selection
or filtering on source success. At each state, sample four native partner turns;
for each turn run two independent continuations. Include the complete user tool
sequence, its effects and its eventual text reply. This gives 48 sampled partner
turns and 96 continuations. Both roles retain the previous measured condition:
AutoDL `gpt-5.6-luna`, temperature 1.0, reasoning none.

The native task builder restores each prefix and both databases. Each sampled
partner block is then held fixed by replay while the suffix is independently
sampled. All task environment assertions are recorded before the partner turn,
after it, and after continuation. Final benchmark reward is independently
computed by the native evaluator. Assertion vectors are available for later
subtask analysis; no assertion is automatically declared relevant to a turn.

No early rejection of states whose first few outcomes agree. Negative unbiased
sensitivity estimates remain in reports. The small batch establishes execution
and guides the next experiment; it does not establish a concentration effect.
No human annotation or hypothesis-test threshold is required to execute it.

## Commands

Run from the repository root:

```bash
.venv/bin/python pilot/p4_v6.py --prepare-only
.venv/bin/python pilot/p4_v6.py
.venv/bin/python pilot/p4_v6.py --report-only
```

The default credential file is `api.txt`; it is read into environment variables.
All provider requests are recorded using the existing redacted request ledger.
Rerunning the same output directory reuses saved partner turns and suffixes.
The saved protocol determines its states and k/m, including on resume. To change
sample size or k/m, use a new output directory:

```bash
.venv/bin/python pilot/p4_v6.py \
  --out pilot/runs/p4/v6_next --states 40 --k 6 --m 4 --workers 12
```

Outputs are under `pilot/runs/p4/v6_20261004/`: `protocol.json`, `preflight.json`,
`replies/`, `continuations/`, `trajectories/`, `requests/`, `summary.json`, and
`report.md`. Request usage counts partner sampling exactly once plus all suffix
calls; provider error responses without usage cannot contribute measured tokens.

## Typicality and subsequent work

The live Luna probe accepted `logprobs=true` but returned `logprobs: null`.
`logprob_probe.json` records this response and its usage. Actual typicality is
therefore unavailable in this condition. VS verbalized probabilities will not
be treated as model log-likelihood. The first batch measures sensitivity only.

Next, inspect the high-sensitivity states and their complete partner blocks,
compare P0/VS-Multi/outcome-feedback probes on those states, and include some
low-sensitivity states to measure what a q-based locator misses. For a larger
concentration estimate use independent reply/continuation groups for ranking
and estimation; m=2 must not be split into two m=1 sensitivity measurements.
Then use a working open-model endpoint for genuine logprob/anti-sharpening
experiments and conduct fresh task sampling beyond the saved base trajectories.

## Follow-up diagnostics in the same session

`p4_v6_reference.py` reuses four states and exactly the same 16 sampled partner
blocks, then runs two suffixes per block with `gpt-5.6-sol`. Outputs and the
Luna/Sol comparison are in `runs/p4/v6_reference_20261004/`. One provider timeout
was preserved in the request ledger; rerunning reuses completed suffixes and
executes only missing ones.

`p4_v6_probe.py` explores state `s003`, whose four native samples all returned
exactly the same phone-number sentence. It compares a single-batch VS baseline
with the same generation plus outcome feedback. Three text candidates per arm
are checked for fidelity by Sol, and each accepted candidate gets two Luna
continuations. This is a text-only diagnostic, not the full tool-action probe
or iterative VS-Multi implementation. Outputs are in
`runs/p4/v6_probe_20261004/`.

```bash
.venv/bin/python pilot/p4_v6_reference.py --states s002 s004 s006 s009
.venv/bin/python pilot/p4_v6_probe.py --state s003
```

Partner blocks are compared after dropping random tool-call IDs and accounting
metadata. Reports include the distinct block count. `candidate_bank.json` pools
replications of identical behavior before estimating candidate effects; the
raw per-draw sensitivity estimate is retained for its sampling interpretation.
A positive noisy sensitivity estimate for four identical replies is not evidence
of four different behaviors. Follow-up fidelity assessments are model judgments;
no human labels have been manufactured.

## First-round results

All three batches completed: 96 native-reply continuations (16 successes),
32 stronger-agent continuations (8 successes, all in the successful control),
and 12 text-probe continuations (10 successes). In the text probe, both VS batch
and outcome feedback achieved 5/6 successes versus 4/8 under the identical
native phone-number reply. These are small exploratory samples; the two probe
arms have not been distinguished by this experiment.

The sole native-pilot estimate slightly above 0.04 came from four identical
partner replies, so it does not support a partner-behavior effect. Identical
blocks are pooled in the exploratory candidate bank. The measured result
supports investigating generated alternatives even at states whose ordinary
partner sampling provides little behavioral variation. Broader fresh tasks,
more repeats, and a genuinely logprob-capable partner are the next measurements.

`runs/p4/v6_20261004/audit.json` records all 140 trajectories, token accounting,
prefix integrity, request statuses, and the artifact credential scan. Six
existing native-branch tests, the exact unbiased-estimator expectation check,
and Ruff lint/format checks passed.
